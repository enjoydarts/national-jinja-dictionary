# 明示された複数全文読みと登記名称画像の個別審査案

状態: 提案。実装・正本への採用は未承認。

## 目的と根拠

保留調査で実資料の根拠が揃っても、既存の審査型では根拠を表現できない2種類を扱う。原文・施設ID・登録ID・原文hash・既存判断を保持し、推定読みや一般の字形置換は追加しない。

- 味淵神社: 神社庁の同一正式名・同一かな欄が `ミジブチジンジャ（アジブチジンジャ）` と2つの全文読みを明示する。複数正式名の分割ではない。
- 素盞烏命神社: 神社庁実コード1069の表示と全所在地に対し、国税庁CSVは `素＿烏命神社`、登録全文カナは `スサノオノミコトジンジャ`。同CSV行の名称画像00044945は正式名全体を表示する。CSVの代理文字を推測置換しない。

## 方法の比較

1. 専用の狭い審査型を追加する（推奨）。既存の原文・補正・審査の分離を保ち、必要な証拠と拒否条件を機械検査できる。
2. 派生登録を正本へ直接追加する。既存収集処理との重複・再取得時の保持を別管理する必要があり、今回の編集判断を既存の審査層で管理する方針に合わない。

既存の複数正式名用 `split`、法人種別接頭辞の除去、別の `source_kind` を流用して検証を通す方法は採らない。

## 同じ正式名の2全文読み

新しい `source_review` の種別を、同一名のかな欄に全文読み2つが丸括弧で併記された場合へ限定する。

- 対象ID・原文hash・原名・原全かな・原全住所・実掲載URLを現在の正本へ拘束する。
- 同一実コード、単一の正式名見出し、唯一のかな欄と所在地欄を記録した神社庁参照を必要とする。施設同一性の未解決や既存の除外を解除しない。
- 原かなの文字区間は `[0,8)` と `[9,17)`。残りは全角丸括弧2文字のみ。出力は各区間のひらがな正規化そのもので、語尾追加・削除・綴り修正を認めない。
- 出力は同じ原表記の2登録に限定し、元登録を残したまま派生元へ結ぶ。施設数は増やさず、派生IDは元登録・表記・読み・専用種別から安定生成する。
- 別名・旧称・括弧付き地名・複数施設・途中かなには適用しない。現在/旧市名の対応が必要な場合は既存の個別条例根拠へ拘束する。

## 登記名称画像による代理文字の対応

国税庁参照の生CSV名を残したまま、個別に目視した名称画像の全文転写を同一性の証拠として使用する。

- 法人番号・月次版・実file ID・CSV行・ZIPメンバー・CSV本文hash・原全所在地・名称画像IDを束縛する。後続8日次の状態確認と存続法人の一意性を保持する。
- `image_reviews.nameImageId` の実URL・画像hash・目視方法と、転写した名称全体を必要とする。
- CSV名と転写名は同じ文字数で、変更できるのは実際の代理文字位置のみ。代理文字以外の字形・社号・順序は一致しなければ拒否する。
- 転写名は原神社庁の正式名全体と一致させる。原一覧の実href・同コードの神社庁詳細・全地番を照合した証拠を保持し、町域だけの名前一致へ一般化しない。
- 読みは画像から推定せず、同じ存続法人行に明示された全文フリガナだけを使用する。CSV原名や `source_kind` を変更しない。

## 検証と導入

変更対象は審査・補正の検証処理と対応テスト・データ仕様文書に限定する。共有作業への干渉を避けるため、一時的な隔離worktreeで実装・検証し、統合時に共有正本の最新変更を再確認する。実装前に正常例と拒否例のテストを作り、未対応の失敗を確認してから最小実装を行う。

原文hash・ID・コード・全住所・日次根拠・画像ID/hash・代理文字位置・転写名・かな区間の欠落や改変、既存の除外、同一性未解決、重複読み、別表記、語尾補作を拒否する。既存の審査型と派生IDを変えず、全テスト・正本検証・実資料の独立照合後に対象2件だけを採用する。
