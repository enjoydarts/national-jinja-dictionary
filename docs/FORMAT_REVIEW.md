# 取り込み確認の手順と不足資料

施設ごとの読み・外字の判断は [REVIEW.md](REVIEW.md) です。ここでは取り込み確認用の少量ファイルの使い方と、まだ不足している実製品資料を示します。正本検証・ATOK（標準Shift JIS／UTF-16BE）・Google日本語入力 for macOS・Mozc・macOS追加辞書・JSON・CSV生成に対応しています。**全IMEで実際の取り込み・変換は未確認**です。

## 確認用ファイルの生成

```sh
python3 -m njd --output-dir dist/ime-samples build --samples-only --formats all --sample-name 倭文神社 --sample-name 大國神社
```

これはネットワーク取得も全国版の一括生成も行いません。`all`には未対応のMicrosoft IMEを含むため終了コードは2です。`samples/national/manifest.json`が原文・出典と選択された登録、同じ場所の`report.json`が形式別の出力行数・除外理由・保留理由です。施設が複数あっても、読み・表記・品詞が同じ行は1行になります。ATOKの標準Shift JIS版は表現できない異体字を理由付きで除外するため、Unicode版等と行数が違う場合があります。

各製品の公式手順で試験用の新規辞書へ取り込み、生成レポートの行数と照合します。取り込んだ単語の読みで変換し、原文の字体が候補に残ることも確認します。OSのビルド、IME版、設定、受理・拒否件数、書き戻し結果を記録します。人工試験語や個人の登録単語を辞書の正本に加える必要はありません。

| 出力 | 取り込みの入口・確認事項 |
| --- | --- |
| `atok.txt` | ATOK for Macの辞書ユーティリティで試験用辞書を開き、環境設定のShift JIS読み書きを「日本語（Shift JIS）」に設定。「ファイルから登録・削除」の単語一括処理でATOK形式として指定。設定は[公式案内](https://www.atok.com/other/support/howtouse/mac/mn/pgs/mn_tool_d_com_encoding.htm)、一括処理は[公式案内](https://www.atok.com/other/support/howtouse/mac/mn/pgs/mn_tool_ut_syori_word_d.htm)を参照 |
| `atok_unicode.txt` | ATOK for Mac 36.0.2の試験用辞書で、同じ単語一括処理からATOK形式として指定。BOM付きUTF-16BEファイルを文字コード変換せず渡す。Shift JISの設定に依存しないUnicode入力経路を使用する |
| `google.txt` | Google日本語入力 for macOS 3.34.6260.1の辞書ツールを開き、管理メニューから「新規辞書にインポート」。文字コードをUTF-8として指定。原文の字体とレポートの出力行数を照合 |
| `mozc.txt` | 対象版の辞書ツールから新規辞書へインポート。TAB3列・UTF-8・固有名詞を確認 |
| `macos.txt` | macOS日本語入力の設定で**追加辞書**として読み込む。[公式の追加辞書手順](https://support.apple.com/ja-jp/guide/japanese-input-method/jpim10226/6.3/mac/27)に従う。ユーザ辞書のテキスト置換には投入しない |
| Microsoft IME | 現時点では対応ファイルを生成しない。以下の製品資料を得てからプロファイルを確定する |

## F001：ATOKの最小確認

個人の通常辞書には触れず、製品の公式手順で**新規の一時辞書**を作り、少量の試験語だけを登録して「一覧出力」の「単語出力」でテキストへ書き出す方法が考えられます。既存辞書の全単語や個人情報を含める必要はありません。

確認に使うのは元のファイルです。チャットや表計算ソフトへ貼り付けた文字列では、BOM・改行・符号化が失われるためバイト単位の比較ができません。版、出力時の文字コード設定、ファイルそのものを対応させます。読み・単語の上限付近を試せる場合は、実際に受理された長さも記録します。

公式手順：[単語ファイルを作成する](https://www.atok.com/other/support/howtouse/mac/dc/pgs/dc_word_file.htm)。現行資料は**単語100文字**です。旧版資料の64文字制限とは区別します。

## F002・F003：実製品からの書き出し

新規の試験用辞書へ少量を登録し、製品の辞書ツールから書き出した元ファイルと製品版を対応させます。試験語は実際の取り込みサンプルに含む短い名称や、明示的な人工試験語で十分です。形式確認の人工試験語を全国神社辞書の正本へ追加することはありません。

Googleは、指定版の公式製品実装で確認した3列TSVの範囲だけをMozcと共通化しています。実製品はコメントを含む4列を書き出すため、コメントなし3列の生成ファイルとの比較では先頭3列を照合します。MicrosoftのCOM APIやスペルチェックAPIの仕様は、IMEの一括登録用テキスト仕様へ流用しません。公式ドメインにあるコミュニティ回答も、Microsoftが公開した仕様と同一には扱いません。

## 比較と反映

追加するプロファイルは、公式仕様・実装または実製品の元バイト列で文字コード・BOM・改行・列数・ヘッダー・品詞を確認し、対象版と照合して反映します。ATOK Unicode版とGoogleは版・SHA-256を固定した公式実装の静的確認に基づきます。生成ファイルの形式チェック、公式実装の静的照合、製品パーサーの実行、実際のインポート、変換結果の確認は別の検証です。[仕様文書](FORMATS.md)の再照合コマンドは製品を起動せず、個人の辞書を変更しません。

現時点の不足を推測で埋めたファイルは配布しません。詳細な仕様・品詞対応・確認範囲は [FORMATS.md](FORMATS.md) にあります。
