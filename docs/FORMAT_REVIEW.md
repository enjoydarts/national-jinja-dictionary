# 出力形式の確認に必要な資料

施設ごとの読み・外字の判断は [REVIEW.md](REVIEW.md) です。ここは残る3形式について、実製品の資料が必要な項目をまとめています。通常の正本検証・Mozc・macOS・JSON・CSV生成は継続できます。

| 番号 | 形式 | 確認済み | 必要な追加資料 |
| --- | --- | --- | --- |
| F001 | ATOK for Mac 36.0.2 | 公式ヘルプのヘッダー・3列TAB・固有地名・読み32／単語100文字、Shift JIS読書き設定 | 同版から実際に書き出した単語ファイルの元バイト列。BOM・改行・文字コード対応、境界の文字計数を確認 |
| F002 | Google日本語入力 desktop | 公式ヘルプとMozc側の形式 | 製品の版・OSと、実製品で書き出した少量の辞書。現在のdesktopとMozcの互換性を比較 |
| F003 | Microsoft IME | Windows 10/11の公式UI説明・単語登録COM API | Windowsのビルド・IME版・新旧モードと、辞書ツールが書き出した少量のテキスト。列・品詞・符号化・ヘッダー等を比較 |

## F001：ATOKの最小確認

個人の通常辞書には触れず、製品の公式手順で**新規の一時辞書**を作り、少量の試験語だけを登録して「一覧出力」の「単語出力」でテキストへ書き出す方法が考えられます。既存辞書の全単語や個人情報を含める必要はありません。

確認に使うのは元のファイルです。チャットや表計算ソフトへ貼り付けた文字列では、BOM・改行・符号化が失われるためバイト単位の比較ができません。版、出力時の文字コード設定、ファイルそのものを対応させます。読み・単語の上限付近を試せる場合は、実際に受理された長さも記録します。

公式手順：[単語ファイルを作成する](https://www.atok.com/other/support/howtouse/mac/dc/pgs/dc_word_file.htm)。現行資料は**単語100文字**です。旧版資料の64文字制限とは区別します。

## F002・F003：実製品からの書き出し

新規の試験用辞書へ少量を登録し、製品の辞書ツールから書き出した元ファイルと製品版を対応させます。試験語は実際の取り込みサンプルに含む短い名称や、明示的な人工試験語で十分です。形式確認の人工試験語を全国神社辞書の正本へ追加することはありません。

Google製品とMozcは由来が共通でも、現行製品の取込形式が同じとは断定できません。MicrosoftのCOM APIやスペルチェックAPIの仕様も、IMEの一括登録用テキスト仕様へ流用しません。

## 比較と反映

元バイト列から文字コード・BOM・改行・列数・ヘッダー・品詞を確認し、公式資料の対象版と照合してからプロファイルへ反映します。生成ファイルの形式チェック、実際のインポート、変換結果の確認は別の検証です。

現時点の不足を推測で埋めたファイルは配布しません。詳細な仕様・品詞対応・確認範囲は [FORMATS.md](FORMATS.md) にあります。
