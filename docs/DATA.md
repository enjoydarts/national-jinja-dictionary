# データ仕様

## 正本と生成物

[`data/sources/`](../data/sources/)に都道府県ごとの正本を1ファイルずつ置きます。各ファイルは`schema_version=3`・`prefecture_code`・`sources`を持ちます。`sources`内の各情報源に`facilities`・`entries`・`collection`があり、各施設・登録の採用値と、`source_record`の原観測、`judgments`の根拠付き判断を管理します。登録の調査履歴は同じレコードの`research`にあります。`research_index.json`は全国共通の調査索引です。

正本ローダーは原観測と判断を既存の検証器へ投影して採用値と照合します。旧補正ファイルは読み足しません。各IMEと管理用JSON・CSVは、この検証済みの共通データから直接出力します。

| レコード | 主なフィールド |
| --- | --- |
| 施設 | `id`, `agency`, `listed_name`, `name_raw`, `prefecture_code`, `prefecture`, `municipality`, `address` |
| 登録 | `id`, `facility_id`, `surface`, `reading`, `semantic_type` |
| 出典 | `listing_url`, `reading_url`, `source_locator`, `source_hash`, `page_hash`, `fetched_at`, `checked_at`, `evidence` |
| 原文 | `name_raw`, `reading_raw`。補正前の値を保持 |
| 状態 | `status`と`reason` |
| 取得範囲 | `collection`内の取得数・掲載範囲・制限・利用条件 |

`semantic_type`はIMEに依存しない`proper_noun`です。IME固有の品詞名・文字コード・BOMは[出力側](FORMATS.md)で管理します。

`source_hash`は掲載名・読み原文・所在地の組み合わせ、`page_hash`は取得ページ全体のSHA-256です。hashは保存した資料との対応を検査するもので、内容の正しさや利用許諾を証明するものではありません。

## 状態と収録条件

| 状態 | 意味 |
| --- | --- |
| `verified` | そのレコードに必要な根拠を確認済み |
| `pending` | 読み・所在地・資料の相違などが未解決 |
| `excluded` | 理由付きで出力対象外 |

施設の`verified`は名称・所在地の掲載確認、登録の`verified`は読みの根拠確認です。辞書出力には施設と登録の両方が条件を満たす必要があります。補正候補の`needs_review`は採用済みを意味しません。

読みは全角ひらがなに正規化します。読みのNFKC・カタカナからひらがなへの変換と、発音の推定は区別します。途中までの読み、漢字から補った語尾、別施設の読みは採用しません。旧字体・異体字を出力用表記で置換しません。

括弧付きの地名が名称に併記されている場合は、地名と確認できた注記を登録表記から除きます。例えば「神明社（小山町）」は「しんめいしゃ → 神明社」と登録し、掲載名の原文・地名・所在地・施設ID・出典を保持します。同名でも別施設のレコードは統合せず、それぞれに掲載された全文読みを採用します。適用した施設と根拠は`entries[].judgments.reviews`の`annotation_review`に保存します。対象は確認した地名注記で、「下社」など名称や施設区分に関わる注記は個別に確認します。

神社庁の明示読みを優先します。不足や外字の補正には施設公式・Wikipedia・行政資料などの実資料を使い、同じ名称・所在地の施設であることと全文読みを照合します。資料の相違が解決しなければ保留します。`jinja-net.jp`は候補発見の入口に限り、辞書の出典としては検証で拒否します。

## 出典区分

| 区分 | 保存する根拠 |
| --- | --- |
| 神社庁資料（既定の`agency`） | 神社庁の掲載URL、原文、公式性の確認情報 |
| `wikipedia_reference` | 記事URL・固定版URL・記事ID・版ID・名称/読み/所在地の原文・ライセンス |
| `association_reference` | 発行団体・掲載URL・原文・団体の確認情報 |
| `municipal_reference` | 自治体が発行した公刊資料の名称・全文かな・所在地の原欄、資料URL・取得ハッシュ、発行者の確認根拠・利用条件 |

参考資料単独枠は神社庁掲載確認済みへ分類せず、`official_agency_listing_verified=false`を保持します。Wikipediaは47都道府県を調査対象とし、記事本文で名称・全文読み・所在地・神社であることを確認した施設だけを採用します。これは47都道府県の取得・確認完了を意味しません。団体資料は宮崎県神道青年会を対象とします。

Wikipedia資料の施設・登録は、既存の情報源キーとIDを保ったまま当該県の正本内に保存します。例えば愛知県の`aichi`と`aichi_wikipedia`は`aichi.json`内の`sources`にあります。採用前に既存施設の名称・所在地・出典を照合し、同一施設の読み補完は既存登録へ根拠付き補正として保存します。同一性が未解決の候補を新施設として重複計上しません。

自治体の公刊資料は、現鎮座地を示す地番または住居表示と、社名に直接対応する全文かなを確認した施設を収録します。`source_reference`に掲載箇所、発行者を示す同一サイトの資料、利用条件を保持します。新規登録時には同じ市町村の同名や同じ所在地に既存施設がある候補を個別審査に回します。県の正本に`<県のキー>_municipal`として収め、出力の`source_basis_counts`とリリースの`ATTRIBUTION.json`に出典区分を記録します。

Wikipediaの記事タイトルやカテゴリ所属だけで施設・読みを確定しません。本文と施設情報表の名称・全文読み・所在地・神社である記述を照合します。個別に本文を確認した参照は`acquisition_method=individual_source_review`で区別します。複数施設の記事では各施設の名称・所在地・該当節を分けます。

Wikimediaの公式ダンプで確認した参照は `source_reference.archive_observation` に配布元、版の日時、索引と対応する取得範囲、圧縮ストリームのSHA-256、名称・読み・所在地の該当Wiki原文を保存します。この参照の `page_hash` は記事のWiki原文をUTF-8で符号化したSHA-256です。索引とXMLのページIDが一致することを確認し、XMLの版IDから版固定URLを記録します。

冒頭節に同名の神社が複数あると明記された記事は、情報表が1つでも自動採用せず、施設ごとの個別確認へ回します。既存正本との重複だけでなく、新規候補同士の所在地の重なりも確認し、別施設か情報表の誤りかが未解決の候補は加算しません。

## IDと施設の同一性

住所から導出する`municipality`は原住所と分離します。汎用の「市市」優先抽出は町域の先頭の市まで取り込むため使用せず、四日市市・廿日市市・野々市市と旧今市市・八日市市のみ原名を保持して先に照合し、その他は最初の市と区を抽出します。現行3市名は取得済み国税庁差分CSV（2026年11月2日・9日）の`cityName`、旧2市名は[栃木県の合併表](https://www.pref.tochigi.lg.jp/a02/pref/shichouson/gappei/1174633899527.html)と[滋賀県の合併状況](https://www.pref.shiga.lg.jp/bh00/7752.html)の本文で確認しています。これは神社の読みや旧新住所の同定根拠ではなく、現旧自治体の完全な判定器でもありません。既存正本の導出値を補正する場合は、旧値・対象ID/hashと判断を`collection.municipality_derivation_review`の配列に保存し、原住所・原名・原文hashを保持します。この履歴は再取得時にも重複なく保持しますが、古い住所やhashに対する補正値を新取得の原住所・市町村へ再適用しません。

情報源に施設単位のコードがあれば、そのコードと情報源識別子から安定IDを生成します。コードがない場合は初回の名称・住所を使います。同名・別所在地は別施設です。記事更新の版IDを施設IDには使いません。

改称・住所変更で新しいIDが発生した場合は自動統合せず、情報源正本の`identity_links`へ実資料で照合した対応を保存します。対象の原文hashと旧IDを束縛し、変更履歴を保持します。

同一施設の複数掲載は`facilities[].judgments.source_aliases`で整理します。高知は庁の二つの掲載構造で同じ社名と全地番を照合しています。長崎は旧リンク集と地域別一覧について、庁が掲載した実リンク、施設や包括団体などが公開する対応資料、鎮座地を確認した組を対象にします。元の施設・登録、掲載ID、原文hash、出典、保留判断を保存します。

IME出力時は読み・表記・出力先品詞が同じ行を重複除去します。複数施設が同じ行に対応しても、正本と管理用JSON・CSVにはそれぞれの施設を残します。

## 補正と編集判断

採用値を根拠と照合するときの順序は、取得原文 → 所在地補完 → 名称・読み補正 → 個別の編集判断 → 除外判断 → 掲載重複の整理です。これは同じ正本内での検証であり、外部の補正ファイルを読み足す工程ではありません。

| ファイル | 用途・主な検証 |
| --- | --- |
| `facilities[].judgments.locations` | 神社庁の実リンクと施設公式の名称・所在地を照合した空欄の補完 |
| `entries[].judgments.corrections` | `original`・`changes`・`references`・`identity_match`・対象hashを保存 |
| `entries[].judgments.reviews` | 対象施設/登録・原文・hashと、採用する表記・読み・根拠を保存 |
| `entries[].judgments.decisions` | 登録ID・対象hash・状態・除外理由を保存 |
| 情報源正本の`identity_links` | 新旧施設ID・対象hash・同一施設と判断した根拠を保存 |

原文と判断は同じ正本レコードの別フィールドに保存します。再取得で原文が変わった場合は、判断を削除せず要確認へ戻します。既存の除外や保留を、読み補正だけで解除しません。

`entries[].judgments.reviews`の`confirmation`は、明示的な編集者の確認である`user_confirmation`と、実資料の対応を照合した`source_review`を区別します。`outputs[].basis`も、神社庁の読み選択・正式名ごとの区切り・参考資料・綴り修正・編集者提供の読みを区別します。資料上の全文読みを確認していない場合は、読み確認URLを捏造しません。

`source_review`の`review_kind=single_address_linebreak`は、県・市町村・町域だけの1行と数字・ハイフンの全番地だけの1行が同一の鎮座地欄にある場合の個別審査です。原一覧の社名・独立全文かな・実href、実詳細の社名・住所、取得済み国税庁の唯一の存続法人の原名・全住所を3つの参照として保持し、各hashと施設/登録ID・原文hashへ束縛します。原住所の改行・原名・原読み・ID/hashは変更せず、読みは既存神社庁欄だけを選択します。国税庁の空フリガナを読み根拠にせず、画像付き行・複数所在地・注記付き・先頭行に数字がある住所や別枝番を自動的に審査通過させません。一般の改行住所の検査や既存の分割審査は維持します。

複数の正式名を個別登録する場合は、表記と読みが原文の完全な区切りに対応することを検証します。施設数は増やさず、`parent_entry_id`で元登録を参照します。元の複合登録は理由付きで除外します。

## 所在地と参考資料の照合

所在地の比較用正規化と、保存・出力用の原文は分離します。数字幅、番地表記、数字間の「の」、住所単位の直前にある通常の漢数字などを照合用に扱いますが、異なる地番や市町村を一致させません。

「自7054番地.至7055番地」「自７０５４番地・至７０５５番地」「自7054至7055」のように両端が明記された地番範囲は、「番地」と両端の間の区切りを比較時にそろえます。開始番号・終了番号・町域のすべてが一致する場合に照合し、各資料の原表記を保持します。

長野県神社庁の冊子で個別に原画像を確認した場合は、冊子の「三二七三」のような地番末尾の数字列を「3273」と照合できます。冊子のハッシュ、原掲載の原文ハッシュ、双方の末尾地番を `address_identity_proof` に束縛します。町域と枝番を含めて照合し、各資料の原表記を保存します。

郡の省略は先頭の郡名だけを比較対象とし、市・区を含む町域の「郡」まで削除しません。双方が明記した郡名が異なる場合も一致させません。「市」を含む実在の高市郡・余市郡は省略比較を維持します。郡名は[奈良県の市町村所在地一覧](https://www.pref.nara.lg.jp/n006/9686.html)の高取町・明日香村欄と、[北海道の構造改革特区一覧](https://www.pref.hokkaido.lg.jp/ss/csr/bunken/kouzou_nintei.html)の仁木町・余市町の範囲欄を2026年11月12日に本文で確認しています。これらは住所比較の根拠であり、神社の読みの根拠には使用しません。

施設公式の読みと住所が別ページの場合は、神社庁の実href・原文・hashに結び付いた`official_site_binding`と各ページの参照を保存します。実際に確認した転送だけを連続した証拠として使い、別サイトや別アカウントへ広げません。

字名追加や町域のみの掲載には、実リンクと全住所の対応を記録した`address_identity_proof`が必要です。施設の同定に使った補完住所と神社庁の原住所は別々に保持します。

行政CSVで住所が分割されている場合は、`address_components`に実列名`都道府県名`・`市区町村名`・`住所`と各原値を保存します。参照にはCSV行番号・hash・抽出位置と、各`列名=原値`を明記した抜粋が必要です。`address_raw`はこの3列を順に機械連結した比較用住所とし、原資料に連続して印字されていた引用とは扱いません。空欄や未記載の地番を補わず、名称・全所在地の照合条件を維持します。

高知県の町名`檮原町`・`梼原町`は、町の[農村景観活用交流促進施設条例](https://www.town.yusuhara.lg.jp/reiki_int/reiki_honbun/o342RG00000279.html)と[移住定住雇用促進住宅条例](https://www.town.yusuhara.lg.jp/reiki_int/reiki_honbun/o342RG00000464.html)の本文で両表記の使用を確認しています。この町名が住所の先頭（高岡郡の記載は任意）にあり、地番数字が明記される場合だけ比較上対応させます。原住所・神社名・他地域の字名は置換しません。町名のみの観測に地番を補う根拠にはしません。

佐賀県の[合併前後の住所表記資料](https://www.pref.saga.lg.jp/kiji00329259/3_29259_6_chouazamei.pdf)の1・2ページで確認した佐賀市の7旧自治体と、小城市の旧小城町・神埼市の旧千代田町の計9接頭辞は、`address_identity_proof.kind=documented_municipality_prefix_change`で個別参照に束縛した場合だけ追加照合します。施設ID・登録ID・原文hash・旧新住所・参照URL/hashと、県資料の固定URL/hash・ページ・施行日・表示例・確認日時が必要です。一般の住所正規化は変更せず、原住所・原字形を保持します。独立資料の正式名が原名に対応し、既存の全住所比較で字名・全地番が一致する読みのみ補正に限ります。無地番からの地番補完、別県、資料対象外の自治体、名称変更、小城町の晴氣/晴気・岩藏/岩蔵の字形変更、有田町の字名・番地再編には使いません。根拠を満たした機械検証と、実資料による施設同定の審査は区別します。

長崎県諫早市では、神社庁の「高来町船津名」「森山町大字森山本村名」を、資料の「高来町船津」「森山町本村」と照合できます。`address_identity_proof.kind=documented_isahaya_locality_change` で、施設ID・登録ID・取得原文hash・双方の住所・参照先と、日本郵便の旧町別変更一覧にある当該行のURL/hash・施行日・町域・郵便番号を対応づけます。読みだけを補正する場合に、正式名と枝番を含む全地番の一致を求めます。正本では神社庁と各資料の原住所を保持します。[日本郵便の旧高来町住所変更一覧](https://www.post.japanpost.jp/cgi-zip/zipcode.php?addr=&city=1423431&cmp=1&mode=list&pref=42)・[旧森山町住所変更一覧](https://www.post.japanpost.jp/cgi-zip/zipcode.php?addr=&city=1423411&cmp=1&mode=list&pref=42)・[諫早市の町の名称](https://www.city.isahaya.nagasaki.jp/soshiki/42/1688.html)

富士吉田市小明見の子之神社は、住居表示対照表の旧新・新旧の両欄で異なる住所表記を照合できます。`address_identity_proof.kind=documented_fujiyoshida_residence_pair` で、両方向の行とPDFのURL・hash、現住居番号、文化財所在地、資料のURL・hash、取得原文hashを結び付けます。この対応は小明見3352と小明見五丁目4番17号の当該行に基づき、子之神社の読み補完に適用します。[富士吉田市の住居表示対照表](https://www.city.fujiyoshida.yamanashi.jp/uploaded/attachment/3948.pdf)・[市指定天然記念物](https://www.city.fujiyoshida.yamanashi.jp/page/1107.html)

## 再取得と保存

部分取得で既存施設が欠ける場合は前回の正本を保持します。保存できた範囲・失敗・停止理由は`collection`と共通索引の取得状態記録に記録します。

個別照合した`curated_source_record`が新しい取得案から欠落した場合は保存を拒否します。参照変更は再照合後に`reviewed_curated=True`で保存し、旧参照を`curated_reference_history`へ保持します。

調査候補の保存と正本への採用は別工程です。`njd.proposals`は対象原文・所在地・既存判断との競合を検証し、失敗した案を部分適用しません。更新手順は[開発ガイド](DEVELOPMENT.md)を参照してください。

## 同一CSV行の小字欄による比較用住所

`csv_address_context.kind=same_csv_record_explicit_aza` は、大学公開の市民調査CSVで同じ論理レコードに印字された `No`・`神社名`・`カナ`・`所在地`・`小字` の対応を検証します。参照とコンテキストのURL/hash/確認日時/論理レコード番号/No/原列値が一致し、5列を列名付きで並べた最小抜粋が両方に必要です。`address_raw` は所在地列の原値のままです。元CSVの引用符内改行を含む物理行番号と、ヘッダを1とする論理レコード番号を区別します。

比較時に限り、所在地列の地番前接頭辞・同じ行の小字・全数値地番を結合します。`comparison_separator` は比較表記の「字」又は空文字だけを許し、印字されていない連続住所の引用とは扱いません。原字名・原住所は保持します。小字を別行から取り込むこと、漢字とカナの推定対応、字名の一部削除、旧村名や沿革による補作、枝番文字・複数地番・合番の推測解釈は行いません。読みだけの補正を対象とし、既存の除外・同一性保留・施設保留を解除せず、コンテキスト破損時は通常の完全住所照合にも後退しません。

### 利用者が確認した区切り記号と注記
