# 共通データと人手判断

## 正本

リポジトリの`data/sources/*.json`が都道府県・情報源ごとの正本です。各ファイルは`schema_version`、`facilities`、`entries`、`collection`を持ちます。品詞のIME固有文字列、符号化、BOMは正本の登録レコードに置きません。`entries.semantic_type`は中立な`proper_noun`です。

| 区分 | 主なフィールド |
| --- | --- |
| 施設 | `id`, `agency`, `listed_name`, `name_raw`, `prefecture_code`, `prefecture`, `municipality`, `address` |
| 施設の出典 | `listing_url`, `source_locator`, `source_hash`, `page_hash`, `official_site_url`, `fetched_at`, `checked_at` |
| 登録 | `id`, `facility_id`, `surface`, `reading`, `semantic_type` |
| 登録の出典 | `name_raw`, `reading_raw`, `listing_url`, `reading_url`, `evidence`, `reading_source_kind`, `normalization`, `source_hash`, `page_hash`, `fetched_at`, `checked_at` |
| 状態 | 両レコードの`status`（`verified`・`pending`・`excluded`）と`reason` |
| 取得範囲 | `collection.source_rows_observed`, `selected_rows`, `limit`, `non_facility_rows`, `coverage`, `redistribution_status` |

`source_hash`は掲載名・カナ原文・所在地の組み合わせ、`page_hash`は取得したページ全体のSHA-256です。`source_locator`は掲載箇所の識別用で、施設の同一性は行番号だけで決定しません。

`reading_raw`は神社庁表のカナ欄を保持します。読みのNFKC・カタカナからひらがなへの変換は機械的操作です。空白・制御文字・漢字・英字などを含み、変換後も許容文字にならないものは推定せず要確認にします。表記・旧字体・異体字をこの正規化で変更しません。

施設の`verified`は名称・所在地の掲載確認、登録の`verified`は読みの根拠確認です。読みがない施設でも掲載自体は確認できるため状態を分離しています。辞書へ出せる確認済み施設数は、検証を通る登録と施設の両方が`verified`である施設IDの数です。

## 神社庁のリンク集に所在地がない場合

[`data/locations.json`](../data/locations.json)は、施設ID別の所在地補完を保持します。神社庁の掲載名・実際の施設公式リンクと、リンク先に明記された同名神社の所在地を照合した資料です。神社庁原文の空住所・空市区町村、施設ID、原文ハッシュは変更しません。

`facilities`内の各補完は、`expected_source_hash`、取得原文の`original`、補完値の`changes`、神社庁の実アンカーの`agency_link`、施設公式の所在地の`reference`を持ちます。所在地は神社のアクセス・鎮座地として確認し、社務所・ナビ入口・競合する候補とは区別します。既存の住所を書き換える用途には使いません。名称の違い、別施設・別アカウントの参照、都道府県・市区町村の不一致は保留します。

実際に観測した転送がある場合だけ、`redirects`へ各HTTP 3xxのURL・転送先・hash・取得日を保存できます。連続する転送を検証し、最後の実URLの範囲で参照先を照合します。`www`の有無を推定で同一視しません。

適用した結果は施設の`location_supplement`に原文・根拠とともに残り、有効な`address`・`municipality`だけを補います。読みの補完は別の`data/corrections.json`です。神社庁の住所は`original.address`に空欄のまま保存し、読み補正の`identity_match`でも`agency_address`と`effective_address`を区別します。原文の行ハッシュは、補完後の住所ではなく神社庁の原文で検証します。

`research.facilities`は、参照したページ・未確認項目・停止理由・表記差などの調査根拠です。施設の`location_research`としてJSON・CSVにも出します。このmetadataだけで住所・読み・確認状態は昇格しません。SNSの取得停止や404も、本文確認済みとは扱いません。

適用順序は、神社庁の取得原文→所在地補完→読み・表記補正→人手判断→除外判断です。元の掲載情報や補完の根拠が変わり照合できなくなったものは、保存した判断を消さず保留へ戻します。リリースは所在地補完も入力hashに含め、ネット接続なしで再現します。施設公式ページの所在地補完を自動で再取得する処理は未実装です。更新時は参照先を実確認し、補完の差分をレビューしてコミットしてください。

## IDと再取得

施設単位の掲載コードがある場合は神社庁識別子とそのコードからUUIDを生成します。一覧ページ・氏子地域ページのIDを施設IDへ流用しません。群馬など恒久的な施設コードがない資料では、初回の施設IDを神社庁識別子・掲載名・住所から生成します。同名・別所在地は別IDです。同じ資料からの再生成では同じIDになります。

掲載名や住所の変更は単純な名称一致で統合しません。再取得で削除・追加が発生した場合、新規行を`pending`へ隔離し、人手で同一施設か確認します。隔離は再取得しても維持します。`collection.identity_history`とGit履歴に旧ID・名称・所在地・出典根拠を保持します。

`data/identities.json`は、新しく観測した施設IDをキーとし、次の対応を保持します。

```json
{
  "NEW_FACILITY_ID": {
    "facility_id": "EXISTING_FACILITY_ID",
    "expected_source_hash": "CURRENT_SOURCE_ROW_SHA256",
    "reason": "実資料で改称・住所表記変更と同一施設を照合した具体的理由"
  }
}
```

これは入力構造の例で、実施設データではありません。対応先は永続履歴にあるIDに限り、複数の掲載行を同じIDへ統合する対応は拒否します。ID対応後も、人手判断の対象行hashが変わっていれば再確認が必要です。

途中取得・件数制限・未取得ページがある結果だけでは、前回保存した施設を削除しません。その場合は前回の正本を保持し、manifestに`failed_using_previous`と理由を残します。新しい部分取得が前回の全施設IDを含む場合は拡張として保存できます。完了した掲載範囲からの削除・改称の検出と区別します。

## 修正・除外判断

`data/decisions.json`は登録IDをキーにする別ファイルです。収集処理は既存ファイルを上書きしません。

```json
{
  "ENTRY_ID": {
    "expected_source_hash": "SOURCE_ROW_SHA256",
    "status": "excluded",
    "reason": "除外と判断した具体的理由"
  }
}
```

元の掲載行が変わった場合は、判断を消さず適用結果を`pending`に戻します。取得済みの`reading_raw`・`name_raw`・表記・hashは判断ファイルから書き換えられません。神社庁由来の読みは元のrawとの正規化一致と行hashを検証します。

`jinja-net.jp`の全国・県別検索は、候補名を発見する入口としてだけ使用します。同サイトを神社庁掲載の根拠・全文読みの出典・補正の参考資料として登録することは認めません。名称から別途、神社庁・個別神社公式サイト・Wikipedia等の実ページへ進み、対象施設と所在地を照合して、その確認先だけを辞書の出典に保存します。検証は同サイトの掲載URL・読み確認URL・補正/人手判断の参照URLを拒否します。

通常の読み補完は神社庁の読みがない場合に当該神社の公式サイトで行います。ユーザーの追加指定により、壊れた読み・名称欄や外字にはWikipedia・行政資料・他の参考資料も補正根拠として利用できます。神社庁掲載の条件は変えません。

### 根拠付き補正

`data/corrections.json`は取得原本と別の正本です。登録IDごとに次を保存します。

- `facility_id`、対象の`expected_source_hash`、原文の`original`スナップショット。
- `changes.surface`・`changes.reading`、理由、施設同一性を照合した`identity_match`。
- 実際に開いた`references`のURL・名称・所在地・読み原文・短い抜粋・確認日・掲載箇所。取得できた場合だけ実際のページhash。
- `verified`／`needs_review`。候補だけの補正は採用しません。

照合用に空白・数字幅・郵便番号・郡の省略・大字／番地・「88番地の1」と「88-1」・数字の間の丁目/番/号/マイナス記号等の表記差を比較する処理があります。出力名や取得原文をこの比較値で書き換えません。参考資料の名称と所在地が対象施設に対応し、変更する全文の読み・表記がその資料の抜粋に明示されている場合だけ適用します。所在地が町名までしか掲載されない資料では照合の精度にも限界があるため、個別の電話番号等の補助根拠と判断記録を参照してください。機械検証は実資料を読んだ人の判断を代替しません。

公式性未確認の一覧、施設同一性の衝突、複数所在地などの隔離を、名前だけの補正で解除しません。名前の表示欠陥を直しても、読みが未確認なら辞書へ出しません。原文・hashは不変です。原文が更新されれば補正を要確認へ戻します。ネイティブ施設IDと原文3項目・行hashが同じで、同一エンドポイントのページ送り・セッション用クエリだけが変わった場合は補正を維持します。元の実際の出典URLは補正記録に保持し、架空の固定URLへ書き換えません。手動の除外判断は補正の後に適用し、優先します。

今回の補正には、秋田の明示的な「正式読み＋通称」欄から正式読みだけを採るもの、行政資料によるUnicode外字対応、別資料の全文読みと同一所在地を照合したものがあります。通称・別称・略称の登録は増やしません。Wikipediaを参照する場合も実際に開いた記事・版・利用条件を記録します。Wikipediaを調べたが該当記事を確認できなかった場合、Wikipediaを根拠にはしません。

### 明示された人手判断と複数正式名

`data/reviews.json`はユーザーの明示判断（`confirmation: user_confirmation`）と、実資料に明示された正式名・全文読みの対応を照合した編集判断（`confirmation: source_review`）を区別し、施設ID・登録ID・原文4項目・行hashに結び付けます。適用順序は取得原本 → 根拠付き補正 → 人手判断 → 手動除外です。取得内容が変われば要確認へ戻し、神社庁の公式性未確認や施設同一性の隔離を読みの判断だけで解除しません。

適用した登録には`reading_source_kind: user_review`と`human_review`を保持します。この値は人手の照合層を通した登録を表し、ユーザーから読みを教わったことを一律に意味しません。`source_review`は神社庁の実資料に名称・各全文読み・所在地が揃う個別正式名登録だけを許可し、原文の省略部分や所在地差を承認する用途には使いません。その`outputs[].basis`は、神社庁の全文読みの選択（`agency_selected`）、複数正式名に対応する原文の完全な読み単位（`agency_component`）、参考資料の明示読み（`reference`）、明示された文字位置の綴り修正（`editorial_normalization`）、ユーザーが提示した全文読み（`user_confirmation`）を区別します。後者は読み確認URLを空欄とし、掲載URLを全文読みの確認根拠として流用しません。補正前の参考資料のカナを改変しません。

所在地差の採用は当該施設と参考資料の名称・住所・URLの組み合わせへの明示判断に限定します。一般的な住所正規化規則にはしません。同一施設の神社庁掲載間の読みの相違を解決する場合も、確認した衝突の原文を固定し、名称や住所も違う衝突は解除しません。

併記された正式名の個別登録は、登録名の連結が掲載名の正式名部分と一致し、読みも原文の完全な区切り単位に一致することを検証します。除く総称の接頭部分は明示し、読みの一部や語尾を推定しません。施設レコードは増やさず、個別登録IDを施設IDと正式名から安定生成し、`parent_entry_id`で元登録を参照します。元登録は理由付きで除外します。正本の原文はそのまま保持します。

リリースはこのファイルも入力hash・ZIPへ含め、同じ人手判断をオフラインで再適用します。実際の適用状態は`collection.human_reviews`のapplied・pending・unmatchedで確認できます。

### Wikipediaからの読み補完案

`python3 -m njd.wikipedia`は県別カテゴリの実リンクから記事候補を発見し、既存の神社庁掲載施設のうち読み原文が空欄のものだけと照合します。カテゴリ所属や記事タイトルだけを読みの根拠にはしません。本文の冒頭節で完全一致する神社名と全文カナが明記され、単一の施設情報表の名称・所在地と原文の版番号を取得できる場合に限り、既存の出典検証を通した補完案を作ります。

原文に複数の読みがあるもの、所在地不一致、構造を認識できない記事、未取得の記事は保留です。同一施設に対応する複数候補記事の読みが衝突する場合や未取得候補が残る場合も、自動採用しません。APIやカテゴリのページ送りがrobotsで取得できなければ未訪問範囲として残し、回避しません。

キャッシュ・記事ごとの調査状態・補完案はリポジトリ外へ保存します。`--offline`はキャッシュだけを使い、`--recheck`はHTTPキャッシュを再利用して抽出・照合をやり直します。`--refresh`は必要なときだけ資料を再取得します。処理の`complete`は指定カテゴリで発見した候補の取得・照合工程の状態で、全国の神社や読みの網羅を示しません。記事候補を見つけられなかった施設は`unmatched_entry_ids`として残ります。

`python3 -m njd.proposals --input PATH`で全案を検証し、差分を確認してから`--apply`を付けると`data/corrections.json`へ一括保存します。1件でも古い原文・所在地不一致・既存判断の競合があれば部分適用せず停止します。既存の人手判断・補正・除外を上書きしません。辞書生成やReleaseはこの調査処理を呼びません。

### 神社庁詳細の優先と法人番号公表データ

`njd.agency_details`は島根の既存一覧に記録された詳細URLと、長野の既存一覧の同一名称・同一所在地行に実在する詳細リンクをたどります。正称に対応する読み欄と鎮座地を照合し、別称・祭神・語幹だけのカナは採用しません。原文は変更せず、リンクの取得根拠と詳細の原文・hashを補完案に保存します。

`njd.proposals --prefer-agency`は、同じ対象原文に結び付いた神社庁の明示読みを、既存の二次資料による読み補正より優先できます。以前の参照資料と相違した読みは保持します。既存の人手判断・除外・名称補正、原文の変更、神社庁の読み同士の衝突は自動上書きしません。

`njd.corporate`は[国税庁法人番号公表サイトの全件データ](https://www.houjin-bangou.nta.go.jp/download/zenken/)の実際の県別ダウンロードフォームを使用します。無償・登録不要の公開データで、API契約を行いません。CSVの項目は[公式リソース定義4.1](https://www.houjin-bangou.nta.go.jp/pc/download/images/k-resource-dl.pdf)に基づく30列です。対象月、ファイルID、CSVメンバー名・行番号、法人番号、名称・所在地・フリガナ原文、取得hashを保存します。ダウンロードのCookie・一時トークンや、関係のない法人行は辞書の正本に保存しません。

既存の神社庁掲載施設に対し、名称完全一致と地番までの住所一致、一意な存続法人、明示された全文カナを必要とします。法人種別だけで宗教法人を判定せず、名称の接頭辞を省略しません。閉鎖・削除・非公開・未確認の画像外字・フリガナなし・複数法人の衝突・明らかな部分読みは保留です。[公式FAQ](https://www.houjin-bangou.nta.go.jp/shitsumon/shosai.html?selQaId=00107)が説明する大書きカナを「ジンジヤ」から「ジンジャ」へ推測修正しません。

採用した国税庁由来レコードには[利用規約](https://www.houjin-bangou.nta.go.jp/riyokiyaku/)に基づき出典と加工表示、[公共データ利用規約1.0](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0)への参照を保存します。国税庁のフリガナを神社庁の掲載読みに見せかけず、神社庁の読みが新たに確認できた場合はそちらを優先します。

## 検証と原文照合

`validate`は必須項目・URL・状態・日時・文字種・IDの一意性・施設参照・原文との正規化一致・行hash等を検証します。辞書出力はこの検証を通った`verified`登録だけを対象にします。

`audit --source gunma`は群馬に実装した独立照合です。リポジトリの群馬原本とキャッシュ内の取得資料について、アダプターとは別の行抽出処理で名称・カナ原文・所在地を全件照合します。人手判断を重ねる前の取得原本を対象にします。補完先のウェブページの意味や発音の正しさを自動で判断する処理ではありません。補完先は人手で実資料との照合を行い、根拠を残す必要があります。

## データ利用条件

全県でこの独立照合コマンドを実装したとは主張しません。全県共通の`validate`と、アダプター単位の取得結果照合を区別します。

取得可能なこと、robots.txtで拒否されないこと、名称・読みが明示されていること、公開再配布が許されることは別の判断です。`redistribution_status: unconfirmed`のデータを、MIT許諾済みのデータセットとして扱いません。ローカルの取得ページ本文・画像・キャッシュ・個人の作業台帳を公開しません。辞書の正本・補正根拠・公開用情報源一覧はリポジトリで管理します。Obsidianは作業記録だけです。

### 小字の追加と同一施設への実リンクによる限定照合

補正参考資料の `address_identity_proof` は任意の追加根拠です。`kind=additional_aza_with_subject_link`、`added_aza_raw` と `subject_link` を記録します。リンクは参考資料のURL・ページhashに結びつけ、対象神社庁プロフィールを示す関係・実href・ページ内位置・観測HTTP応答列（URL、status、page_hash、fetched_at、転送時location）を保存します。直接200または同じhost/path/queryのHTTP→HTTPS転送に限定し、最終200のURL・hashが神社庁掲載ページと一致することが条件です。

住所は共通の表記比較を行った後、同一の町名までの部分と全地番・枝番が一致し、その間に参考資料が明示する `字` または `小字` と非空の名称が追加されている場合だけを照合します。原文は変更しません。別市町・異なる地番・沢/澤の差・町の欠落・空欄を解消する一般的な曖昧一致ではありません。施設ID・印字コード・出典の衝突など、外字とは独立した保留理由も解除しません。

### 一覧の番地が省略された施設の個別照合

滋賀の344詳細の個別調査では、神社庁一覧の実hrefとHTMLのbase要素から解決した詳細URL、一覧と同じ施設ID・名称、詳細の番地を含む鎮座地を確認し、国税庁の一意な存続法人の名称・全住所と照合しました。一覧の所在地原文は変更せず、詳細の原文・カナ・URL・hash・取得と確認日時・リンク元の原文を補正のreferencesとidentity_matchに保存しています。

神社庁詳細のカナが語幹だけの場合、その語幹に語尾を加えていません。登録する全文読みは国税庁の明示全文フリガナを根拠とし、神社庁のカナと食い違うものは保留しました。一般の `njd.corporate` の番地必須条件は変えていません。今回の個別照合を、一覧の町名だけで別施設のフリガナを一括採用する処理へ広げません。54候補をstatus=needs_reviewの補正として、全文読みを確認した290件と分けて保存し、辞書には出力しません。都久夫須麻神社は国税庁との読み相違を神社庁の語幹と観光情報の明示全文読み・同一所在地で解決し、国税庁の相違原文は未採用参考欄に保持しています。

詳細タイトルに併記された別称は `alias_display_raw`、表示全体は `name_display_raw`、最初のカナは `reading_raw` として分けます。別称を読みとして扱わず、辞書の表記にも追加しません。未知・曖昧な詳細書式は補完せず保留にします。

神社庁の同一施設詳細に名称全体のカナが明記される場合は、その全文読みを優先します。国税庁候補が不一致でも、当該候補に読みの採用を依存させません。不一致の原文と以前の保留理由は別欄に保持し、神社庁の実リンク・施設ID・掲載名・所在地による同定を根拠にします。

国税庁資料を使う補正で、同じ神社庁のカナに `reading_scope` を付けて保存した場合は、全文読みとの整合性も検証します。語幹が全文読みの先頭と一致するだけでは確認済みにしません。全文資料にある読みのうち語幹の後ろが名称末尾の許容読みだけかを比較し、別の音が挟まる場合は保留にします。この比較から新しい読みを生成することはありません。


## Wikipedia参考資料単独の収録

和歌山・広島・山口・徳島・大分・宮崎の参考資料単独枠は `listing_basis=wikipedia_reference` を施設と取得範囲に持ち、`source_publisher=日本語版Wikipedia` を記録します。神社庁の `agency` は付けず、`official_agency_listing_verified=false` とします。既存神社庁資料の区分は `agency` が既定です。`listed_name` と `reading_raw` は、それぞれ実記事の主名称と明示全文カナです。

施設の `source_reference` に記事URL、版固定URL、`article_id`、`revision_id`、名称・カナ・所在地の原文、page hash、確認日、ライセンスを保存します。通常の施設IDは版IDではなく記事IDを種にし、版更新で別施設を増やしません。同名でも記事ID・所在地の異なる施設を統合しません。定型の自動抽出では本文の主名称と神社infobox名の一致、祭神欄または実HTMLメタデータの明示「神社」テンプレート、県内である根拠を持つ一意な所在地、全文カナを検査し、寺院・一覧・番組記事を施設とみなしません。

`reading_source_kind=encyclopedia` はこの明示的な参考資料枠でのみ有効です。根拠のURL・版・ライセンスが欠ける、登録原文と参照が異なる、別の読みURLへ置き換わる、神社庁由来と偽称する場合は検証エラーにします。読み・表記・品詞の重複除去は既存形式と共通です。

記事の未抽出・非施設候補は `collection.article_reviews` に保存し、氏名や所在地を推定した施設レコードは作りません。記事の試行件数、本文確認件数、施設数、県内の全神社数を区別します。`report.json` の `source_basis_counts` は神社庁資料と参考資料枠を分けて数えます。区分別の辞書行数は全国の重複除去前の部分集計のため、合計が全国辞書行数になるとは限りません。

リリースはWikipedia由来の出典と版・利用条件を `ATTRIBUTION.json` に同梱します。ソースコードのMITは収集元データの再許諾ではありません。記事本文全体・画像・取得キャッシュは公開しません。


参考資料の所在地欄で県名が省略される場合も、原文住所に県名を付け足しません。同じ主名称・全文読みを示す冒頭文が、県名と一致する市区町村を所在地として明記するときだけ、`prefecture_context_raw`・`municipality_context_raw`・`location_context_excerpt` に短い原文を保持して県を照合します。別市町や別県の記述、他地域からの分祀を所在地の根拠にしません。

冒頭段落に地名や旧称のふりがながあることと、主名称に複数の読みがあることは区別します。主名称の直後の全文読みだけを採用し、別の明示語句に属する地名・旧称の読みを辞書へ追加しません。裸の追加カナや同じ主名称に再び別読みが付く場合は保留します。

別名URLが同じ記事ID・同じ原文に対応する場合は1施設とし、`listing_occurrences` と `additional_source_references` に各URLの版・hash・取得日時を残します。主名称・全文読み・所在地が食い違う観測は自動採用しません。住所欄に埋め込まれたGeohackの座標リンクは住所文字列から構造的に分離し、差がある場合だけ `address_cell_raw` に元セルの表示テキスト、`address_extraction` に処理内容を保存します。漢字・異体字・番地は置換しません。

Wikipediaの施設情報表は主名称を説明する冒頭節のものだけを対象にします。後続節の博物館・祭礼・別施設の表を主施設の所在地へ流用しません。既知のGeoGroup座標一覧はID・class・表示内容の一致時のみ施設情報表から除き、冒頭節の複数施設は保留します。祭神欄がなくても、実HTMLの `data-mw` が唯一の `Template:神社` を明示する場合は `shrine_type_template_raw` に根拠を保存します。寺院・公園・人物などのテンプレートで代替しません。

郵便番号 `〒NNN-NNNN` が住所の先頭にある場合は原住所を保存したまま、県と市区町村の照合時だけ区別します。全文カナの直後に漢字の別表記・旧字注記が付く括弧は単一読みとして扱いますが、カナが複数ある場合は自動選択しません。


住所欄の単一の折り返しは、郵便番号と県住所の間、または県・郡と町村の間に限って機械的に結合します。`address_lines_raw` に元の各行、`address_layout_normalization` に空白処理を保持します。現社地・元宮・社務所などの併記はこの処理で選択しません。

名称末尾の漢字の切れ目と発音の切れ目が一致するとは限らないため、資料が主名称に直接付した全文カナが「しゃ」「ぐう」で終わる場合も検証対象にします。標準的な接尾辞の読みへ置換せず、語幹へ音を追加しません。

### 施設公式の複数ページの照合

読みと番地までの所在地が別ページに載る場合は、補正の `references` を分けます。読みの参照に他ページの住所を `address_raw` として混入させません。この結合は `official_site_binding.agency_link` が神社庁原文の名称・所在地・href・行位置・page hashと一致し、記録済み転送が連続する場合に限ります。読みと所在地の両参照が同じ公式URLの範囲内にあり、正称が一致し、所在地参照が原住所の照合を通ることを要求します。別サイト、別アカウントを選ぶquery、URL範囲外、別住所を明記する読み参照、途切れた転送には適用しません。各ページのhash・日付・抽出位置・原文をそれぞれ保持し、実資料との照合は別途行います。


### 本文の個別照合と同記事内の複数施設

`acquisition_method=individual_source_review` は、定型情報表以外の本文や複数施設の記事を実際に照合した参照です。主名称・全文カナ・所在地と対応箇所を原文で保存し、神社型は祭神記述等または同じ主名称・読みと結びつく肯定の所在地文 `shrine_type_statement_raw` で確認します。鳥居・橋・芸能・総称、過去の廃社や否定文を、肯定の施設所在地として受け入れません。所在地が説明文なら `address_kind=location_description` を付け、番地へ補いません。

1記事で複数施設を説明する個別参照は `facility_scope=individual_facility` と `section_locator` を持ちます。記事IDに原名称・原住所のfingerprintを加えた内部source IDで分け、同じ記事IDだけで別施設を統合しません。既存の記事単位の施設IDは変更しません。個別名称・所在地の変更は、保存保護と既存の `identities.json` による照合を通して施設IDを維持します。記事全体と個別施設の区分が同じ原文組に重なる場合は、自動で2施設を作らず再照合を要求します。

原資料が複数施設を同じ名称・全文読みの対象として説明している場合も、各施設とその説明・個別所在地を残します。識別用の見出し表示は `name_display_raw` に保持し、語としては本文で明示された主名称を使います。共有する境内・所在地と、2つの神社の名称・読みが明示される場合は、その対応の原文と順序を保存します。別称や略称の追加とは区別します。

個別参照の施設には `curated_source_record=true` を付け、取得案が施設を欠落させる場合は保存を拒否します。取得済みと表示された完全snapshotにも適用します。参照が変わる場合は個別照合後の `reviewed_curated=True` を要求し、旧参照を `curated_reference_history` に保持します。保護フラグと旧参照履歴は再取得案から消えても復元します。これは資料の保存保護であり、状態を根拠なく確認済みにする指定ではありません。

### 神道青年会の独自紹介資料

`data/sources/miyazaki_youth.json`は宮崎県神道青年会の独自発行資料で、`listing_basis=association_reference`、`reading_source_kind=association`、`official_agency_listing_verified=false`を持ちます。発行者の実ページ・hash・確認日は`authority_reference`に、一覧の実掲載枠は施設の`source_reference`と`source_observations`に保存します。詳細URLは実hrefを内部source IDとして使い、改称等による変更は従来の施設ID照合を通します。神社庁・Wikipediaへ再分類しません。

原見出し`header_raw`から名称と全文カナを分離します。後置された地域名は、同枠の住所に実在する文字列で、神社名の接尾辞でない場合のみ`header_location_suffix_raw`へ分離します。住所中の「大字」「字」の除去はこの照合だけに使用し、原住所・出力名は書き換えません。別称・複数名称・語幹カナ・項目のずれは保留します。郵便番号は元の空欄・記号を保持し、県・施設同一性や読みの推定に使いません。

既存の別情報源と名称が一致する場合、または数値間の番地表記・県名・大字の比較処理後に住所が一致する場合は`collection.identity_reviews`に原観測と候補IDを保存します。同名別施設の可能性もあるため、この検出だけで統合しません。抽出前の保留は`observation_reviews`に置き、未確定な施設数を作りません。正本の各施設と、未採用の掲載枠を混同しないでください。`profile_audit`は一覧と同じ発行者の別詳細ページの対照であり、独立した第三者確認やIME取り込みの成功ではありません。

団体資料の再利用条件は未確認です。WikipediaのCC BY-SAやコードのMITを適用しません。リリースの`ATTRIBUTION.json`では`association`と`wikipedia`を分けます。生成物の`source-reviews.json`は未確定な資料・同一性候補の参照用で、施設の`pending.json`とは別に扱います。


### 同一施設の複数掲載行と原IDの保持

`source_aliases.json`は、同一施設の別観測として照合した行を、代表の施設IDと重複側の施設ID、各原文hash・元CMS ID・名称・住所欄/地域欄・出典で束縛します。高知の2種類の掲載構造だけを対象にし、名称一致・番地を含む完全住所一致と県名の有無だけの比較を必要とします。別名・別地番・住所の曖昧一致へ一般化しません。

元の施設・登録レコードや人手判断ファイルを削除せず、`apply_saved_source_aliases`を補正・人手判断の適用後に実行します。重複側の施設に`source_alias_of`、登録に`source_alias_entry_of`、元の照合情報に`source_alias_resolution`を保存した有効ビューを作ります。JSON/CSVは元レコードも含む管理用データです。IMEへは代表だけを渡し、通常の読み/表記/POS重複除去も引き続き行います。

再取得で原文または束縛したURL・位置・page hash・取得日時が変わる、人手や補正の保留がある、代表がない、確認済みの読みが一致しない、または複数登録の対応が未確定な場合は要確認に回し、既存の除外を復活させません。取り込みサンプルには、選択した代表と対になる除外済み観測も根拠の文脈として含めます。サンプルの管理レコード数はIME語数と区別してください。`facilities`、`facility_records`、`source_alias_records`を別に数えます。全レコード数や神社庁の掲載行数を、重複整理後の施設数と同一視しません。


### 政府登録画像の個別確認

`government_corporate_register`の参照に`source_fields.nameImageId`または`addressImageId`がある場合、各画像の`image_reviews`が必要です。実画像のURL/ID/hash・取得日・確認日・目視確認方法/記録と、元CSVの法人番号・snapshot・ZIP hash・行番号・名称・全住所を束縛します。元の名称・全文カナ・所在地・法人番号が参照値と一致し、存続/最新/公開の条件が成立することも検証します。画像参照がない、別の行・snapshot・法人・画像である、または読みが元CSVと違う場合は出力できません。

原画の字形をUnicodeコードポイントと断定して表記を置換せず、画像URL/hashと国税庁のUnicode原文を区別して保持します。画像にない県名を画像原文へ追加しません。カナは元のCSV欄からしか採用せず、画像検査が欠落読み・語幹・大書きカナの推定修正を許すものではありません。通常の自動収集は画像行を保留し、個別に検査した参照だけを正本の補正へ保存します。


### 庁掲載の町域とリンク先の字名地番

町域までしか所在地が掲載されていない場合、同名だけで外部の施設を一致させません。`official_site_binding`の実href・原掲載名・原所在地・locator/hashを照合し、その公式サイト内の同一名称と全所在地を確認した場合のみ、`address_identity_proof.kind: agency_linked_locality_with_aza`を使用します。県名を除いた原町域に、資料に明示された字名・地番だけが追加されることを確認します。既存の地番、他市町村、他のサイトの施設との置き換えは許しません。庁の原町域と公式の全住所は別の原文として保持します。

公式に全文読みとして印刷された語間空白は、`reading_scope: full_name`と`reading_normalization: ["remove printed reading spaces"]`を明示した場合だけ、半角/全角空白を除去できます。元の空白付き読みとその出典は補正参照に残します。TAB・改行・語幹・大書きカナの推定修正をこの方法で許可しません。
