# データ仕様

## 正本と生成物

[`data/sources/`](../data/sources/)が情報源ごとの正本です。各JSONは`schema_version`・`facilities`・`entries`・`collection`を持ちます。生成時に[補正・編集判断ファイル](../data/README.md)を適用し、各IMEと管理用JSON・CSVへ直接出力します。

| レコード | 主なフィールド |
| --- | --- |
| 施設 | `id`, `agency`, `listed_name`, `name_raw`, `prefecture_code`, `prefecture`, `municipality`, `address` |
| 登録 | `id`, `facility_id`, `surface`, `reading`, `semantic_type` |
| 出典 | `listing_url`, `reading_url`, `source_locator`, `source_hash`, `page_hash`, `fetched_at`, `checked_at`, `evidence` |
| 原文 | `name_raw`, `reading_raw`。補正前の値を保持 |
| 状態 | `status`と`reason` |
| 取得範囲 | `collection`内の取得数・掲載範囲・制限・利用条件 |

`semantic_type`はIMEに依存しない`proper_noun`です。IME固有の品詞名・文字コード・BOMは[出力側](FORMATS.md)で管理します。

`source_hash`は掲載名・読み原文・所在地の組み合わせ、`page_hash`は取得ページ全体のSHA-256です。hashは保存した資料との対応を検査するもので、内容の正しさや利用許諾を証明するものではありません。

## 状態と収録条件

| 状態 | 意味 |
| --- | --- |
| `verified` | そのレコードに必要な根拠を確認済み |
| `pending` | 読み・所在地・資料の相違などが未解決 |
| `excluded` | 理由付きで出力対象外 |

施設の`verified`は名称・所在地の掲載確認、登録の`verified`は読みの根拠確認です。辞書出力には施設と登録の両方が条件を満たす必要があります。補正候補の`needs_review`は採用済みを意味しません。

読みは全角ひらがなに正規化します。読みのNFKC・カタカナからひらがなへの変換と、発音の推定は区別します。途中までの読み、漢字から補った語尾、別施設の読みは採用しません。旧字体・異体字を出力用表記で置換しません。

神社庁の明示読みを優先します。不足や外字の補正には施設公式・Wikipedia・行政資料などの実資料を使い、同じ名称・所在地の施設であることと全文読みを照合します。資料の相違が解決しなければ保留します。`jinja-net.jp`は候補発見の入口に限り、辞書の出典としては検証で拒否します。

## 出典区分

| 区分 | 保存する根拠 |
| --- | --- |
| 神社庁資料（既定の`agency`） | 神社庁の掲載URL、原文、公式性の確認情報 |
| `wikipedia_reference` | 記事URL・固定版URL・記事ID・版ID・名称/読み/所在地の原文・ライセンス |
| `association_reference` | 発行団体・掲載URL・原文・団体の確認情報 |

参考資料単独枠は神社庁掲載確認済みへ分類せず、`official_agency_listing_verified=false`を保持します。Wikipediaは和歌山・広島・山口・徳島・大分・宮崎、団体資料は宮崎県神道青年会を対象とします。

Wikipediaの記事タイトルやカテゴリ所属だけで施設・読みを確定しません。本文と施設情報表の名称・全文読み・所在地・神社である記述を照合します。個別に本文を確認した参照は`acquisition_method=individual_source_review`で区別します。複数施設の記事では各施設の名称・所在地・該当節を分けます。

## IDと施設の同一性

情報源に施設単位のコードがあれば、そのコードと情報源識別子から安定IDを生成します。コードがない場合は初回の名称・住所を使います。同名・別所在地は別施設です。記事更新の版IDを施設IDには使いません。

改称・住所変更で新しいIDが発生した場合は自動統合せず、`identities.json`へ実資料で照合した対応を保存します。対象の原文hashと旧IDを束縛し、変更履歴を保持します。

同一施設の複数掲載は`source_aliases.json`で整理します。現在は高知の照合済みの掲載構造を対象とし、原ID・原文hash・出典を保存します。元レコードは削除しません。未解決の同一性を、名称一致だけで確定しません。

IME出力時は読み・表記・出力先品詞が同じ行を重複除去します。複数施設が同じ行に対応しても、正本と管理用JSON・CSVにはそれぞれの施設を残します。

## 補正と編集判断

適用順序は、取得原文 → 所在地補完 → 名称・読み補正 → 個別の編集判断 → 除外判断 → 掲載重複の整理です。

| ファイル | 用途・主な検証 |
| --- | --- |
| `locations.json` | 神社庁の実リンクと施設公式の名称・所在地を照合した空欄の補完 |
| `corrections.json` | `original`・`changes`・`references`・`identity_match`・対象hashを保存 |
| `reviews.json` | 対象施設/登録・原文・hashと、採用する表記・読み・根拠を保存 |
| `decisions.json` | 登録ID・対象hash・状態・除外理由を保存 |
| `identities.json` | 新旧施設ID・対象hash・同一施設と判断した根拠を保存 |

原文と判断は別々に保存します。再取得で原文が変わった場合は、判断を削除せず要確認へ戻します。既存の除外や保留を、読み補正だけで解除しません。

`reviews.json`の`confirmation`は、明示的な編集者の確認である`user_confirmation`と、実資料の対応を照合した`source_review`を区別します。`outputs[].basis`も、神社庁の読み選択・正式名ごとの区切り・参考資料・綴り修正・編集者提供の読みを区別します。資料上の全文読みを確認していない場合は、読み確認URLを捏造しません。

複数の正式名を個別登録する場合は、表記と読みが原文の完全な区切りに対応することを検証します。施設数は増やさず、`parent_entry_id`で元登録を参照します。元の複合登録は理由付きで除外します。

## 所在地と参考資料の照合

所在地の比較用正規化と、保存・出力用の原文は分離します。数字幅、番地表記、数字間の「の」、住所単位の直前にある通常の漢数字などを照合用に扱いますが、異なる地番や市町村を一致させません。

施設公式の読みと住所が別ページの場合は、神社庁の実href・原文・hashに結び付いた`official_site_binding`と各ページの参照を保存します。実際に確認した転送だけを連続した証拠として使い、別サイトや別アカウントへ広げません。

字名追加や町域のみの掲載には、実リンクと全住所の対応を記録した`address_identity_proof`が必要です。施設の同定に使った補完住所と神社庁の原住所は別々に保持します。

国税庁資料は正式名称・全地番・一意な存続法人・明示された全文カナを照合します。大書きカナを推測修正しません。法人種別の接頭辞や登録画像のある行には追加の証拠を要求します。画像行は個別の`image_reviews`に画像ID・URL・hashと元CSV行の対応がなければ保留します。

## 再取得と保存

部分取得で既存施設が欠ける場合は前回の正本を保持します。保存できた範囲・失敗・停止理由は`collection`と`manifest.json`に記録します。

個別照合した`curated_source_record`が新しい取得案から欠落した場合は保存を拒否します。参照変更は再照合後に`reviewed_curated=True`で保存し、旧参照を`curated_reference_history`へ保持します。

調査候補の保存と正本への採用は別工程です。`njd.proposals`は対象原文・所在地・既存判断との競合を検証し、失敗した案を部分適用しません。更新手順は[開発ガイド](DEVELOPMENT.md)を参照してください。

## 検証と件数

`validate`は必須項目・URL・日付・文字種・ID一意性・施設参照・原文正規化・hash・補正の対応を検証します。`audit --source gunma`は群馬の正本と取得キャッシュを別の抽出処理で照合します。この独立照合は全情報源に実装されたものではありません。

| 件数 | 意味 |
| --- | --- |
| `facility_records` | 元掲載の施設管理レコード。未確認・除外・別観測を含む |
| `source_alias_records` | 同一施設の別掲載として整理した観測数 |
| `facilities` | 上記を整理した施設数 |
| `verified_facilities` | 出力条件を満たす登録を持つ施設数 |
| `dictionary_rows` | 共通データの読み・表記を重複除去した行数 |
| `output_rows` | 形式ごとの文字コード・長さ等の制限を反映した行数 |

取得行数、記事数、施設数、県内の全神社数は異なります。JSON・CSVは未確認・除外も含む管理用データで、行数はIME語数ではありません。未確認データの案内は[REVIEW.md](REVIEW.md)を参照してください。

## 利用条件

取得可能であること、robotsが許可すること、辞書としての再配布が許されることは別の判断です。`redistribution_status: unconfirmed`を許諾済みとは扱いません。

出典・版・加工表示・利用条件は正本とリリースの`ATTRIBUTION.json`へ引き継ぎます。Wikipedia・国税庁・CODH・団体資料などの条件を区別し、コードのMITで上書きしません。取得本文全体・画像・HTTPキャッシュは配布しません。[情報源一覧](SOURCES.md)に条件と未確認事項を記載しています。
